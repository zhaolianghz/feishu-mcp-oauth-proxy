# 浏览器连接独立飞书账号

用户已确认：从 ChatGPT 设置的「连接另一个账户」进入，复用个人身份下已有应用，登录、确认授权后返回 ChatGPT；不要求 SSH、粘贴 Secret 或运行脚本。

## 方案

保留代理密码/GitHub 登录门，在其后增加浏览器连接页。每次授权都进入该页，不因已有代理会话而跳过。用户可确认已有账号、选择已配置应用重新登录，或打开飞书官方应用接入页面；官方页面允许的已有应用接入流程保持可用，不设置 createOnly。可选 App ID 只用于定位已有应用，无须输入 Secret。应用凭据由飞书服务端协议返回给 MCP 后端，经 lark-cli stdin 存入独立凭证目录，再发起用户授权。

不采用聊天参数传递 Secret。商店应用跨租户方案涉及另一套应用发布模型，不在本次范围。

## 边界

- 代理只提供浏览器 UI 和外层 OAuth；内部接口只在 MCP 服务上暴露并验证服务器 Bearer 凭据。
- 应用接入和用户授权分别有过期、拒绝、失败状态；服务端轮询遵守飞书 interval/slow_down，并阻止并发重复消费。
- 每个浏览器流程绑定 session、已登录用户、CSRF token 和外层 OAuth 参数。成功前不签发授权码，完成时要求确认实际账号。取消时返回原始 state 与 access_denied。
- 授权码、access/refresh token 绑定 account_id 和独立 grant connection_id；刷新保持绑定。固定账号被删除后拒绝访问，禁止回落另一账号。
- ChatGPT 请求的身份头由代理覆盖。固定账号连接不能通过 switch 工具变成另一身份；旧 token 仍走原有迁移逻辑。
- 提供符合 OpenAI profile tool 契约的稳定账号 ID、昵称，便于区分企业与个人连接。
- 保留原有未提交改动；本次不自动部署、推送或更改真实飞书应用。

## 验收

自动化覆盖：已有代理会话仍能选择另一账号；相同 client_id 的两次授权互不串号；刷新保持账号；跨 session/用户、CSRF、失效账号、伪造身份头、未完成/过期/拒绝授权不能成功；应用接入后继续用户授权，失败不绑定；Secret 不出现在浏览器响应与工具结果。模拟飞书外部边界验证完整本地链路，真实企业/个人页面仍需用户登录联调。
